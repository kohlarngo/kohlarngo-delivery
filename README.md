# อิ่มด่วน — คู่มือติดตั้ง (อัปเดต: สมัครสมาชิกจริง + อัปโหลดรูป + Google/Facebook)

## ไฟล์ในชุดนี้
- `schema.sql` — โครงสร้างฐานข้อมูลหลัก (รันไปแล้วครั้งก่อน ไม่ต้องรันซ้ำ)
- `migration_auth.sql` — **ไฟล์ใหม่ ต้องรันเพิ่ม** เปิดระบบสมัครสมาชิกจริง + สิทธิ์การเข้าถึงแบบผูกกับบัญชี + ที่เก็บรูปเมนู
- `imduan.html` — แอปลูกค้า: สั่งอาหาร, ล็อกอินด้วย Google/Facebook (หรือสั่งแบบไม่ล็อกอินก็ได้), เห็นรูปเมนูจริง
- `merchant.html` — แอปร้านค้า: **สมัคร/เข้าสู่ระบบด้วยอีเมล-รหัสผ่านจริง**, อัปโหลดรูปเมนู, รับออเดอร์
- `rider.html` — แอปไรเดอร์: สมัคร/เข้าสู่ระบบด้วยอีเมล-รหัสผ่านจริง, รับงาน, ส่ง GPS
- `admin.html` — แดชบอร์ด: ต้องล็อกอินด้วยบัญชีที่อยู่ในตาราง `admins` เท่านั้น

## สิ่งที่เปลี่ยนไปจากเวอร์ชันก่อนหน้า
- ร้านค้าและไรเดอร์ **สมัครสมาชิกได้เองจริง** (อีเมล + รหัสผ่าน) แทนการเลือกจากดรอปดาวน์/กรอกชื่อเฉยๆ — สมัครแล้วสถานะเป็น "รออนุมัติ" เหมือนเดิม ต้องรอแอดมินกดอนุมัติก่อนเริ่มใช้งานได้
- ร้านค้าอัปโหลด**รูปเมนูจริง**ได้ (ไม่ใช่แค่อิโมจิ) ลูกค้าจะเห็นรูปในแอป
- ลูกค้า**ไม่ต้องสมัครก็สั่งได้** (ใช้บัญชีชั่วคราวอัตโนมัติ) แต่ถ้าอยากเก็บประวัติถาวร กดปุ่ม "โปรไฟล์" แล้วเข้าสู่ระบบด้วย **Google หรือ Facebook** ได้
- แอดมินต้อง**ล็อกอิน**ก่อนเข้าแดชบอร์ด (เดิมเปิดดูได้เลยไม่มีการป้องกัน)
- สิทธิ์การเข้าถึงข้อมูล (RLS) เปลี่ยนจาก "เปิดให้ทุกคนแก้ได้" เป็น "แก้ได้เฉพาะเจ้าของข้อมูลหรือแอดมิน" ปลอดภัยขึ้นมาก

## ขั้นตอนติดตั้งเพิ่มเติม (ทำหลังจากที่ตั้ง schema.sql ไว้แล้ว)

### 1) รัน migration_auth.sql
Supabase SQL Editor > New query > วางทั้งไฟล์ `migration_auth.sql` > Run
(เพิ่มคอลัมน์เจ้าของบัญชี, สร้างตาราง `admins`, เปิด storage bucket สำหรับรูปเมนู, เปลี่ยน RLS ทั้งหมด)

### 2) เปิดการตั้งค่าที่ต้องทำในหน้า Dashboard (ทำนอก SQL Editor)
ไปที่ **Authentication > Providers**:
- เปิด **"Allow anonymous sign-ins"** → ลูกค้าสั่งอาหารได้โดยไม่ต้องสมัครก่อน (จำเป็นมาก ถ้าไม่เปิดลูกค้าจะสั่งอาหารไม่ได้เลย)
- เปิด **Email** provider (ปกติเปิดอยู่แล้ว) → ใช้สำหรับร้านค้า/ไรเดอร์/แอดมิน
- ถ้าต้องการ Google/Facebook login ให้ลูกค้า: เปิด **Google** และ/หรือ **Facebook** แล้วกรอก Client ID/Secret ที่ได้จาก Google Cloud Console / Facebook Developers ของคุณเอง (ขั้นตอนนี้ต้องทำเองเพราะต้องผูกกับบัญชีนักพัฒนาของคุณ ดูลิงก์ด้านล่าง)
  - Google: https://console.cloud.google.com/apis/credentials
  - Facebook: https://developers.facebook.com/apps
  - Supabase จะโชว์ "Callback URL" ให้คัดลอกไปใส่ในหน้าตั้งค่าของ Google/Facebook ด้วย

ไปที่ **Authentication > URL Configuration**:
- ใส่ URL เว็บไซต์จริงที่คุณจะอัปโหลดไฟล์ไปโฮสต์ ลงใน "Redirect URLs" (จำเป็นสำหรับปุ่ม Google/Facebook login ให้กลับมาที่แอปถูกหน้า)

**ปิดได้ถ้าอยากทดสอบเร็ว:** Authentication > Providers > Email > "Confirm email" — ถ้าปิดไว้ ร้านค้า/ไรเดอร์ที่สมัครจะเข้าใช้งานได้ทันทีไม่ต้องกดยืนยันอีเมล (เหมาะกับตอนทดสอบ แนะนำเปิดกลับตอนใช้งานจริงกับคนทั่วไป)

### 3) ตั้งบัญชีตัวเองเป็นแอดมิน (จำเป็น ไม่งั้นเข้า admin.html ไม่ได้เลย)
1. Supabase Dashboard > Authentication > Users > **Add user** สร้างอีเมล/รหัสผ่านของคุณ แล้วคัดลอก **User UID**
2. SQL Editor รันคำสั่ง (แทนค่าของคุณเอง):
   ```sql
   insert into admins (id, name) values ('วาง-UID-ตรงนี้', 'ชื่อคุณ');
   ```
3. เปิด `admin.html` แล้วล็อกอินด้วยอีเมล/รหัสผ่านนั้น

### 4) ทดสอบสมัครร้านค้า/ไรเดอร์
1. เปิด `merchant.html` → กด "ยังไม่มีร้าน? สมัครใหม่" → กรอกอีเมล/รหัสผ่าน → กรอกโปรไฟล์ร้าน → ส่งขออนุมัติ
2. เปิด `admin.html` → เมนูร้านค้า → กดอนุมัติร้านที่เพิ่งสมัคร
3. กลับไป `merchant.html` (รีเฟรชหน้า) → เข้าใช้งานได้แล้ว → ลองอัปโหลดเมนูพร้อมรูป
4. ทำแบบเดียวกันกับ `rider.html`
5. เปิด `imduan.html` → จะเห็นรูปเมนูที่เพิ่งอัปโหลด → ลองสั่งซื้อ

## อัปโหลดขึ้นเว็บให้ใช้งานจริง
ไฟล์ทั้ง 4 เป็น static HTML ล้วน ไม่ต้อง build อัปโหลดตรงๆ ได้เลยกับผู้ให้บริการฟรีเหล่านี้ (เลือกอันเดียวพอ):
- **Netlify Drop** (ง่ายที่สุด): https://app.netlify.com/drop → ลากไฟล์ทั้ง 4 ไปวาง ได้ลิงก์ใช้งานทันที
- **GitHub Pages**: อัปโหลดไฟล์เข้า repository แล้วเปิด Pages ในการตั้งค่า repo
- **Vercel**: ลากโฟลเดอร์เข้า Vercel dashboard

⚠️ **สำคัญ:** หลังได้ URL จริงแล้ว ต้องกลับไปใส่ URL นั้นใน Supabase Authentication > URL Configuration > Redirect URLs (ขั้นตอนที่ 2) ไม่งั้นปุ่ม Google/Facebook login จะพากลับมาผิดหน้า และ GPS ของเบราว์เซอร์ต้องการ HTTPS ด้วย ผู้ให้บริการทั้ง 3 เจ้าข้างต้นให้ HTTPS มาให้อัตโนมัติ

## ข้อจำกัดที่ยังเหลืออยู่
- ยังไม่มีระบบชำระเงินจริง (ตัดบัตร/พร้อมเพย์) — เป็นแค่ตัวเลือกข้อความ
- "ยอดจ่ายไรเดอร์/ร้านค้ารอโอน" ในหน้าการเงินยังเป็นตัวเลขตัวอย่าง ไม่ได้คำนวณจากธุรกรรมจริง
- ต้องเปิด "Allow anonymous sign-ins" ไม่งั้นแอปลูกค้าจะใช้งานไม่ได้เลย (ดูขั้นตอนที่ 2)
- Google/Facebook login ต้องตั้งค่า OAuth app ของตัวเองก่อนถึงจะใช้ได้ (ไม่ใช่ปุ่มที่ใช้ได้ทันทีแบบไม่ต้องตั้งค่า)
